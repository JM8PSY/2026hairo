# ブラウザ ⇔ 映像サーバー WebSocket（`/ws`）

実装：`parent/server/video.py`、`parent/server/mjpeg.py`、`web/video.js`。設定：`parent/config/video.json`。

映像サーバーは操縦サーバー（`app.py`）とは別プロセスで、ポートも別（既定 8081）。ページ自体は操縦サーバーの `/video?cam=1` で配信し、非常停止はそちらの `/ws` へ送る。

## 接続

`ws://<親機IP>:8081/ws?cam=1&fps=15`。不明なカメラは 404。使えない `fps` は既定値になる。

## 親機 → ブラウザ

| 種類 | 内容 |
|------|------|
| バイナリ | JPEG 1枚（カメラの出力そのまま。再エンコードしない） |
| `{"t":"hello","cam":"1","label":"...","fps":15,"fps_options":[...],"cameras":[{"id":"1","label":"..."}]}` | 接続直後 |
| `{"t":"fps","fps":10}` | フレームレートの変更結果 |

## ブラウザ → 親機

| メッセージ | 内容 |
|------------|------|
| `{"t":"ack"}` | フレームを1枚描画した。受信確認のないフレームは最大2枚で、超えたぶんは捨てる（遅延をためない） |
| `{"t":"fps","fps":10}` | フレームレートの変更 |

## カメラ

- 2880×1440 の MJPEG は、カメラ内でつなぎ合わせ済みの正距円筒図。1台あたり約 356KB/枚、約 29fps（実測）。
- 見ている人がいる間だけ `v4l2-ctl` で開く。全員が閉じて3秒たつと閉じる。カメラのプロセスが落ちたら1秒後に開き直す。
- Insta360 はシリアル番号がどちらも 0001 なので、`/dev/v4l/by-path` の USB ポートの位置で指定する。
